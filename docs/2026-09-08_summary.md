## 一、环境迁移：Windows → WSL2 Ubuntu

| 事项 | 结果 |
|---|---|
| 训练数据迁移 | 5.9GB（13100 wav + 13100 mel 缓存 + filelists）拷入 ext4（`~/projects/Matcha-TTS/data`），robocopy 直写 `\\wsl.localhost`（~123MB/s，50 秒完），替换掉原先指向 `/mnt/d` 的软链接 |
| matcha-tts 本体 | `pip install -e .`（0.0.7.2），Cython 对齐模块编译通过（WSL 有 gcc，无需 Tolerant 回退） |
| 系统依赖 | espeak-ng（apt）；wav2vec2 ASR、BigVGAN（HF 缓存）、HiFi-GAN T2 权重全部软链自 Windows 缓存（`~/.cache/huggingface` → `/mnt/c/...`、`~/.local/share/matcha_tts` → `/mnt/c/Users/.../AppData/Local/matcha_tts`），零重下 |
| WSL 代码仓审计 | 发现 9/7 手工复制漏了 10 个文件（configs/data×3、matcha/data×3、matcha/utils/data×4），已补齐 |

### 迁移中踩的两个坑（复用价值高）

1. **`cp` 自嵌套事故**：WSL 仓里 `data` 是指向 `/mnt/d` 源目录的软链接，`cp -a src dst` 语义下 cp 把源目录**自我嵌套复制**回 `/mnt/d/.../data/data`（2.6 万个垃圾文件）后才报 "cannot copy a directory into itself"。清理时注意：拷贝前必须先 `rm` 软链并用 `robocopy src dst /E /MT:16` 从 Windows 直写（快 15 倍）。
2. **`~/.cache/huggingface` 已被 pip 建过目录**：软链脚本必须检查"是符号链接还是真目录"，真目录有内容先搬走再链接，否则静默用空缓存。

| mamba-ssm | 2.2.5 | GitHub releases `mamba_ssm-2.2.5+cu12torch2.8cxx11abiTRUE-cp311` wheel |
| transformers | 4.57.6 | mamba 运行依赖（generation 工具）；与 diffusers 0.40.0 共存实测无冲突（pip 有 hub 版本警告，可无视） |

**关键过程记录**：

1. 先按惯例走 PyPI sdist → `ninja: error: csrc/causal_conv1d.cpp missing`——**PyPI sdist 缺源文件的打包 bug**。
2. 改 GitHub tag 源码 → causal-conv1d 两个类报错：① C++ 编译找不到 `cuda_runtime_api.h`（conda CUDA 布局 include 路径问题）；② nvcc 12.8 与 Ubuntu 25.10 的 glibc 2.42 冲突（`cospi/sinpi exception specification incompatible`，CUDA 12.8 不支持该 glibc）。
3. **终解：官方预编译 wheel 矩阵直接命中**（torch 2.8 + cu12 + cxx11abiTrue + cp311）。torch 侧实测 `_GLIBCXX_USE_CXX11_ABI=True`，选 abiTRUE 版本。20 分钟编译问题 = 2 个 wget。
4. **选版本注意**：mamba-ssm 2.3.x（当前最新）metadata 依赖 triton>=3.5 / tilelang / quack-kernels，会强升/威胁 torch 2.8 栈；2.2.5 依赖干净且自带 `Mamba`+`Mamba2`。wheel 缓存留在 `~/mamba_build/wheels/`（~700MB）。

## 三、MambaBlock1D 设计与集成

**定位**：U-Net 每级 down/mid/up 里"全局混合器"的对位替换（attention ↔ SSM 1:1），与 ConvNeXt 的 `resnet_type` 同模式。

| 设计点 | 决策 | 依据 |
|---|---|---|
| 双向化 | `out = mamba_fwd(x) + flip(mamba_bwd(flip(x)))`，两个独立实例 | Mamba 因果单向；mel 生成需全局上下文（Vim 式惯例） |
| 零初始化 | 输出分支 `LayerScale(1e-6)` 逐通道缩放 | 09-06 GRN 教训的正面复用：残差主干恒等启动，gamma 梯度逐步打开分支 |
| 初始化保护 | `initialize_weights` 跳过 MambaBlock1D 整个子树 | Mamba2 的 `A_log/D/dt_bias` 是精心设计的特殊初始化，被外层 Kaiming 扫过会破坏 SSM 步长语义（测试用 conv1d.bias 非零断言验证） |
| 时间条件 | timestep 收下不用 | 与现有 BasicTransformerBlock 分支一致，时间由每级 ResnetBlock1D 注入 |
| mask | 不内部处理 | 与现状对齐（diffusers BasicTransformerBlock 本不消费 mask），末端 masking 兜底 |
| Windows 兼容 | `mamba_ssm` 惰性导入（仅 `"mamba"` 分支与 `initialize_weights` 的 try/except） | Windows 无官方 wheel，保证其它路径零影响 |

**改动文件**：`matcha/models/components/mamba_block.py`（新增）、`decoder.py`（工厂分支 + 初始化跳过 + 注释）、`configs/model/decoder/mamba.yaml`（新增）。

**验证（15 项全过）**：单元（形状/恒等启动/双向反向/梯度有限/奇数长度 T=777）→ 初始化跳过证据（conv1d.bias 非零）→ 整 Decoder 前向反向 → 默认 transformer 路径回归 → hydra `train.yaml + model/decoder=mamba` 组合 → CFM 真实路径 construct + 完整训练 loss + backward。参数量：decoder 12.2M（vs transformer 11.8M，+0.4M/+3%）。

## 四、训练与运行观测

- 命令：`python matcha/train.py experiment=ljspeech_min_memory data.batch_size=32 +trainer.accumulate_grad_batches=2 trainer.check_val_every_n_epoch=5 model/decoder=mamba model/scheduler=multistep_late trainer.max_epochs=140 callbacks.model_checkpoint.every_n_epochs=5 callbacks.model_checkpoint.save_top_k=8`（从头训练，run `2026-09-08_13-30-03`）
- 显存 4.6GB（transformer 版 5.2GB）：真 assigned 差 ~0.1GB 量级（flash-SDPA 短序列下 O(T²) 不占优），其余为分配器保留池行为差异
- GPU ~33% 带周期性深谷：谷底=epoch 边界清扫（每 ~2min）与每 5 epoch 验证+matplotlib 画图+258MB checkpoint 写盘；背景锯齿=每 2 微 batch 的优化器阶段。**与 Windows 基线波形同机理（"框架调度刚性地板"），非异常**
- LayerScale 生效证据：ep0 val_mcd≈110（decoder 分支≈0 只剩残差主干）→ ep4 起正常 44 → 34 区间，与"梯度通过 gamma 逐步打开分支"的预期一致

## 五、统一评估协议定版 + 最终对照

**协议：HiFi-GAN T2 声码器 + Denoiser（原论文配方）、LJSpeech val 全量 100 句、ODE 10 步。** 以下所有数字同协议。

| 系统 | 调度 | MCD (dtw) | WER | CER |
|---|---|---|---|---|
| U-Net ep140 | 恒定 LR | 52.85 ±17.16 | 9.3% | 2.5% |
| ConvNeXt V2 ep134（衰减轻训点重评） | 衰减 1e-4→6.25e-6 | **50.88 ±16.22** | 10.4% | 2.6% |
| **Mamba 双向 ep139** | 衰减 1e-4→6.25e-6 | 51.70 ±17.36 | **8.7%** | **2.3%** |

（GT-WER（ASR 上限参照）7.6%；声码器往返下限 3.65dB）

### 逐句配对 Wilcoxon（n=100）

| 对比 | MCD Δ | p | WER Δ | p | CER Δ | p |
|---|---|---|---|---|---|---|
| Mamba vs U-Net ep140（恒定LR） | **−1.16dB** | **0.0015 ✔** | −0.6pt | 0.30 | −0.2pt | 0.67 |
| Mamba vs ConvNeXt ep134（衰减LR） | +0.82dB | 0.23 | **−1.7pt** | **0.023 ✔** | −0.3pt | 0.29 |

### 五条结论

1. **Mamba 追平最强配置**：与衰减 ConvNeXt（此前最佳系统）同协议 MCD 无显著差异（p=0.23）——线性时序骨干没有为质量付出代价，MCD 维度并列第一梯队。
2. **可懂度历史最佳**：WER 8.7% 已逼至 ASR 上限（7.6%），且相对最强对照仍显著更优（p=0.023）——三个系统在同一声码器上下首次拿出配对显著的 WER 增益。
3. **骨干 vs 调度的归因修正**：vs 恒定 LR U-Net 的 MCD 显著改善（−1.16dB）中含 LR 衰减的份额（09-07 已证明衰减单独可贡献 ~1dB 量级）；剥离后骨干差异的真实表达是"MCD 持平 + WER 显著更优"。
4. **工程特性正面**：参数 +3%（12.2M）、显存 −0.6GB、复杂度线性（长序列潜力）；训练全程无 OOM、曲线无剧烈震荡（与"衰减 + 零初始化小参数"的设计自洽，呼应 09-07 的 GRN/LayerScale 机制归因）。
5. **工程方法积累**：换骨干类实验的完整闭环成本已从"一次 Windows 手工周"降到"当日迁移 + 当日落地 + 当日评估"，评估协议统一化（单声码器+Deno）后跨日数字可直接进表。
