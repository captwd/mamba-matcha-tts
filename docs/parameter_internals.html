模型参数的存放与传递 · 完整解剖

以本项目（MatchaTTS，ConvNeXt V2 变体，全模型 22.5M 参数：encoder 7.2M + decoder 15.3M）为实例，从张量内存布局讲到显存地图。所有数字均为本机实测（torchinfo 参数表 + checkpoint 逐键字节统计）。

1. 最底层：一个 Tensor 到底是什么

PyTorch 的每个张量由两部分组成：元数据（轻量，几百字节）和 Storage（真正的连续字节缓冲，可被多个张量共享）。x.view() / x[:, 2] 这类操作不复制数据，只新建一个"指向同一 Storage 的视图"——这就是之前说 forward 里"按引用传递、零拷贝"的物理基础。

🔹 Parameter 是什么：nn.Parameter 只是"requires_grad=True 的 Tensor"再挂进模块的登记簿。除此之外和普通张量无异。

2. 模块树：参数如何被"登记"和"编址"

每个 nn.Module 内部有三个字典：_parameters（可训练张量）、_buffers（不训练但要存档，如 mel_mean/mel_std）、_modules（子模块）。构造函数里 self.xxx = nn.Parameter/Module 的赋值语句就是注册动作。整个模型是一棵树；state_dict() 就是深度优先摊平这棵树，路径名 = 属性名用点号连接 = 加载时的"门牌号"。

🔹 去重规则：两个模块共享同一个 Parameter 时（权重共享），state_dict 只保留一个条目（按对象 id 去重）。本项目无此情况，但阅读 TextEncoder 里 q/k 投影时要知道有这个机制。

3. Autograd：激活从哪来，梯度到哪去

前向时，每一步可微运算都会在动态计算图上登记一个节点，并把反向所需的中间结果（激活）挂在节点上——这就是显存里"激活"的来源，它们由计算图持有，backward() 走完即释放。梯度沿图反向流，最终由 AccumulateGrad 节点写入叶子参数的 .grad（累加语义，这就是梯度累积的物理机制）。

🔹 为什么梯度累积数学等价：.grad += 微批梯度 天然求和；两个均批梯度之和 = 大批平均梯度 ×2，缩放常数被学习率吸收。且本项目用 GroupNorm/LayerNorm（无跨样本统计），batch 切分零副作用。

7. 把常见疑问映射回这套模型

现象/疑问解释
换 ConvNeXt 后为什么不能热迁移权重？门牌号变了（block1.block.0.weight → block1.dwconv.weight）且形状不同；state_dict 加载是严格按名匹配 + copy_
为什么改结构要重训而换声码器不用？声码器不进 state_dict 的匹配范围（独立模型）；声学模型结构变了 = 门牌变了 = 必须重训
.to(device) 之后对象还是原来那个吗？是。Parameter 对象身份不变，只换内部的 Storage 指针（搬到显存）——所以 Python 侧引用全部继续有效
梯度累积为什么省显存？激活随图即时释放，.grad 与参数同形（小）。“攒激活”才贵，“攒梯度”便宜
16-mixed 省的是什么？参数主本仍 fp32（常驻不变）；省的是激活/中间值（fp16）与 Tensor Core 计算。这也是它降显存到不了 50% 的原因
为什么 weights_only=False？ckpt 里 pickle 了 OmegaConf/Python 对象（hyper_parameters），torch 2.6+ 默认安全模式拒绝——你仓库的 _torch_load_compat 兼容层就是为此
推理时为什么显存占用小得多？无反向 → 无激活缓存、无 .grad、无 Adam 状态：常驻只剩参数 ~90MB + 单次前向激活
U-Net 和 ConvNeXt 版差多少参数？U-Net 基线：encoder 7.2M + decoder 11.0M = 18.2M（常驻 ~208MiB）；ConvNeXt：decoder 15.3M，全模型 22.5M（常驻 ~270MiB）。多出的主要是每单元 4× 升维的 pointwise 层
