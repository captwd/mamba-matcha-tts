计算机硬件原理入门 · 为深度学习而学

不讲本机状态，只讲原理：CPU、内存、磁盘、GPU 各自的物理构造、工作方式、以及为什么深度学习会把它们的特性放大成你看到的现象。所有数字按典型消费级硬件给出量级（你的 R9 8940HX / 16GB DDR5 / NVMe / RTX 5060 笔记本基本都落在这些范围内）。

0. 先建立世界观：延迟阶梯

整台计算机的本质是一座为速度妥协容量的金字塔。每往下一层：容量大约 ×10~1000，但速度慢 ×10~10000。一切优化故事的根源都在这张表里。

1.3 "CPU 利用率 33%" 到底在量什么

操作系统调度器每秒采样数百次，统计"有任务可跑的核心·时间 ÷ 总核心·时间"。所以 33% 的意思是：采样时刻平均只有 1/3 的核心"有活干"。它不衡量这些活的含金量（一个忙等循环也能让利用率 100%）。深度学习训练里 CPU 大部分等待来自：等 GPU 同步、等数据、等锁（GIL）。

2. 内存（DRAM）：易失的"工作台"与虚拟内存的戏法

2.1 DRAM 的物理本质

每比特就是一个微型电容（有电=1，没电=0）。电容会漏电，所以 DRAM 每 ~64ms 必须整行刷新一次——这就是"易失性"的由来，也是断电丢数据的根源。CPU 访问 DRAM 需要先激活整行（~几十 ns），这也是随机访问比顺序访问略慢的原因。双通道/四通道 = 多条并行的数据总线，带宽 = 频率 × 位宽 × 通道数（DDR5-5600 双通道 ≈ 89GB/s）。

2.2 虚拟内存：程序看到的地址是"假的"

2.3 页缓存：为什么第二次读文件几乎不花时间

OS 会把读写过的文件内容自动留在空闲内存里（Windows 叫 standby list，Linux 叫 page cache）。这属于"空闲内存的聪明用法"——需要时立刻让位。深度学习数据集（几 GB 的 .npy）第一次读进内存后，之后每个 epoch 都是纯内存命中。这就是"读一次数据，整晚训练磁盘都退休"的原理。

2.4 锁页内存（pinned / page-locked）

普通内存可以被 OS 换出到磁盘，因此 DMA 引擎不敢直接用它做异步拷贝（数据可能中途消失）。锁页内存 = 向 OS 承诺"绝不换出"的页，于是 GPU 的 DMA 引擎可以安全地异步直读。PyTorch 的 pin_memory=True 就是在干这个——代价是锁死的页会加剧内存压力（不能当缓存用），所以它是一把双刃剑。

3.3 NVMe 比 SATA 快在哪

SATA/AHCI 协议只有 1 条命令队列、深度 32；NVMe 走 PCIe 直连，支持 64000 条队列、每条 64000 深。并行度差三个数量级——这就是"同为 SSD，随机读写差好几倍"的协议层原因。训练时的启示：checkpoint 是大块顺序写（NVMe 强项）；数据集若真要读盘也尽量顺序大块读，别每条样本一次小 IO。

4.2 GPU 内部：SM、warp 与"用切换隐藏延迟"

GPU 的最小调度单位是 warp（32 个线程绑在一起，单指令多数据 SIMT）。每个 SM（流式多处理器）同时驻留几十个 warp；当一个 warp 在等显存数据（几百周期）时，调度器立刻切到另一个就绪的 warp 继续算——用海量切换把访存延迟藏起来。这叫延迟隐藏，是 GPU 编程的灵魂。

推论：如果同时驻留的 warp 太少（= occupancy 低，比如你的 batch 只有 32），没有"备胎 warp"可切，GPU 就只能干等 → 任务管理器利用率低。这就是"小 batch 喂不饱 GPU"的架构层解释。

显存侧同理分层级：寄存器 → 共享内存/L1（每 SM 私有，~几十周期）→ L2（全卡共享）→ GDDR/HBM（~300+GB/s，几百周期）。访存模式连续（coalesced）时带宽才能打满——张量的内存布局之所以重要，就在这。

4.3 拷贝引擎：让"搬家"和"计算"同时进行

GPU 里除了计算核心，还有独立的 DMA 拷贝引擎。所以"上一批数据在 GPU 上计算"和"下一批数据从内存拷进来"可以并行——这就是数据预取（prefetch）能提高 GPU 利用率的硬件基础。前提：源内存必须 pinned（见 2.4），否则 DMA 无法安全异步。

5. 四件套如何协同：一次 H2D 拷贝的完整旅程

以"batch.to(device)"这一行代码为例，把四章串起来：

① Python 调用 → ② PyTorch C++ 层把张量指针交给驱动 (WDDM/CUDA) → ③ 驱动向 GPU 拷贝引擎提交 DMA 命令 → ④ PCIe 总线传输（~16-32GB/s；数据须来自 pinned 页，否则先要 CPU 搬运 staging）→ ⑤ 拷贝完成触发中断 → ⑥ 驱动通知 CUDA 流"事件完成" → ⑦ 后续排在同一流里的 kernel 才开始执行
环节参与的硬件典型耗时
CPU 侧准备/命令提交CPU + 系统调用 + 驱动~10µs 级（每次发射的固定开销）
PCIe 传输 32 样本 batchDMA 引擎 + PCIe~毫秒级（几 MB ÷ 16GB/s）

🔹 全局图景：深度学习训练 = 在"延迟阶梯"上反复搬数据，同时让 GPU 的吞吐机器别停。你做过的每个优化（页缓存、pinned、预取、梯度累积、混合精度）都能在这张地图上找到坐标：把数据搬到离计算最近的一层，或者让搬运与计算重叠。
