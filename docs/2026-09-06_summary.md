### LR 衰减干预实验（2026-09-07，假设验证成功 ✔）

**设计**：从同一 ep100 checkpoint（17-01-07 run）续训 40 epoch，唯一变量 = LR 阶梯衰减（MultiStepLR，全局 ep105/115/125/135 各减半，1e-4 → 6.25e-6）。恒定 LR 对照 = 原 19-53-10 run 的 ep130/135/140 三个点。

| epoch | 恒定 LR (MCD) | 衰减 LR (MCD) | Δ（衰减更好为负） | 配对 p |
|---|---|---|---|---|
| ep130 | 51.79 | 51.18 | −0.62 | 0.036 |
| ep135 | 54.40 | 51.02 | −3.37 | <0.0001 |
| ep140 | 56.33 | 52.56 | −3.78 | <0.0001 |

**四条结论**：
1. **因果确认**："恒定 lr=1e-4 扰动 → MCD 震荡/退化"成立——衰减后 ep120 起 MCD 平稳于 51~52.6 区间，恒定组同期震荡至 56.3
2. **剂量-反应关系**：同 epoch 配对差距随 LR 降低逐级扩大（−0.62 → −3.37 → −3.78），且 WER 全程不受影响（p>0.59）——排除"衰减顺带改变了别的"
3. **骨干替换获得正面结论**：ConvNeXt+衰减 最佳（ep135：WER 10.1% / MCD 51.02±16.84）vs 基线 U-Net ep140（9.2% / 52.88±17.12）——MCD **显著更优**（Δ−1.86，p=0.0024），WER 打平（p=0.18）
4. **工程教训两条**：① MultiStepLR 恢复训练时里程碑必须写在全局 epoch 轴上（仓库 configure_optimizers 会把计数器拨到恢复 epoch-1，局部轴里程碑永远够不到——曾静默失效一个 2 小时的 run）；② 训练中途抽查 ckpt 内 lr 验证调度是否生效

### 机制归因：首批证据 + 分析路线图（2026-09-07）

**首批证据（`scripts/analyze_drift.py`，对比恒定 LR 下 ep100→ep140）**：

| 模块组 | 相对漂移 ‖ΔW‖/‖W‖ |
|---|---|
| **estimator GRN gamma/beta** | **0.574** |
| **estimator LayerScale** | **0.554** |
| encoder 文本编码器 | 0.165 |
| estimator Conv/Linear 大权重 | 0.157 |
| estimator Transformer 注意力 | 0.135 |
| estimator time_mlp | 0.052 |

**解读**：恒定 LR 下 40 epoch，归一化类小参数（GRN 的 gamma/beta、LayerScale）漂移超过自身量级的一半，而大权重层只漂 ~15%。GRN/LayerScale 是**逐通道调制增益**——它们摆动直接改变每个位置、每个通道的响应幅度，恰好对应 MCD 所量化的"细节结构变化"；而 MSE 损失对这类低能量方向的扰动不敏感（val loss 平坦）。这与"零初始化小参数 + 大梯度 + 恒定步长 = 持续摆动"的机制完全自洽，也解释了 LR 衰减为何有效（步长收缩 → 小参数稳定）。

**后续机制分析路线图**（供深入研究）：
1. **衰减 vs 恒定的漂移对照**：对衰减 run 的相邻 ckpt（如 ep130→135→140）跑同一脚本——预测小参数组漂移大幅收缩；若成立则因果链闭环
2. **速度场敏感度**：固定 (噪声, mu, t) 输入，比较相邻 ckpt 的 estimator 输出差——量化"场"随权重的摆动幅度
3. **mel 锐度指标**：合成 mel 的局部对比度（帧差能量）/ 高频带能量比，与 MCD 震荡逐点对齐——把"糊化"变成连续曲线
4. **weight soup 验证**：ep130~140 权重平均 → 若 MCD 稳定且优于单点，进一步支持"盆内弹跳"理论

### ConvNeXt V2 训至 140ep 的最终对比 + 质量震荡发现（当日收官）

补充 ep90/95/130/135 中间点后，发现 MCD 并非单调"退化"，而是**围绕均值剧烈震荡**。全量 val 100 句，配方见标注（Deno = 挂 Denoiser，noDen = 不挂）：

| 系统 | 声码器配方 | WER | CER | MCD | gen_len/ref_len |
|---|---|---|---|---|---|
| 基线 U-Net ep140 | BigVGAN + Deno | 9.2% | 2.6% | 52.88 ± 17.12 | — |
| 基线 U-Net ep140 | HiFi-GAN T2 + Deno | 9.3% | 2.5% | 52.85 ± 17.16 | — |
| 基线 U-Net ep130 | BigVGAN noDen | 10.0% | 2.9%* | 56.04 ± 17.81 | 0.997 |
| 基线 U-Net ep135 | BigVGAN noDen | 9.2% | 3.0%* | 55.23 ± 17.81 | 1.001 |
| ConvNeXt ep90 | BigVGAN noDen | 12.6% | — | 56.67 ± 16.69 | 0.984 |
| ConvNeXt ep95 | BigVGAN noDen | 11.0% | — | 52.54 ± 16.18 | 1.010 |
| ConvNeXt ep100 | BigVGAN + Deno | 10.4% | 3.0% | 54.39 ± 16.96 | 1.004 |
| ConvNeXt ep100 | HiFi-GAN T2 + Deno | 10.9% | 3.4% | 54.21 ± 16.88 | 1.004 |
| **ConvNeXt ep130（最佳）** | BigVGAN noDen | 10.4% | 2.9% | **51.79 ± 16.09** | 1.014 |
| ConvNeXt ep130 | HiFi-GAN T2 + Deno | 10.7% | 3.2% | 51.79 ± 16.16 | 1.014 |
| ConvNeXt ep135 | BigVGAN noDen | 10.6% | — | 54.40 ± 16.51 | 0.991 |
| ConvNeXt ep140 | BigVGAN + Deno | 11.3% | 3.3% | 56.35 ± 16.47 | 0.992 |
| ConvNeXt ep140 | HiFi-GAN T2 + Deno | 10.1% | 2.8% | 56.47 ± 16.63 | 0.992 |
| ConvNeXt ep140 | BigVGAN noDen | 10.6% | 2.7% | 56.33 ± 16.46 | 0.992 |

（* = CER 来自曲线批次评估；"—" = 该批次未记录；ep110/120 checkpoint 未存档，曲线空档由 tensorboard val_mcd 补）

**七条结论**：
1. **质量震荡是主现象**：MCD 在相邻 checkpoint（5 epoch）间波动 ±2~4dB（ConvNeXt：56.7→52.5→54.4→51.8→54.4→56.3；U-Net：56.0→55.2→52.9），幅度远大于骨干差异（~1dB）——先前"ep100→140 单调退化"的判断被修正为"震荡恰好取到波峰"
2. **震荡是模型属性**：BigVGAN 与 HiFi-GAN 两条独立采样链在每个 checkpoint 的读数差 <0.3dB、同步起落 → 排除声码器/采样随机性
3. **时长漂移排除**：gen_len/ref_len 比全程稳定 0.98~1.03，DTW 对齐难度无趋势变化
4. **去噪器无影响**：同一 checkpoint 挂/不挂，数字几乎相同
5. **声码器等价性（核心论据）**：HiFi-GAN vs BigVGAN 同 ckpt 逐句配对，3 模型 × 2 指标 = 6 组检验全不显著（p 0.13~0.93）——"mel 对齐即可免重训换声码器"双骨干验证成立
6. **"各自最佳"对比**：ConvNeXt ep130（51.79）vs U-Net ep140（52.92）——ConvNeXt 最佳点 MCD 反超基线；WER 侧 U-Net 仍略优（9.2~9.5 vs 10.4~10.7）
7. **机制假设（头号）**：恒定 lr=1e-4 无衰减（checkpoint 实测），临近收敛的大步长使权重在损失盆内弹跳，estimator 场随之在"质量口袋"间振荡；MSE 型 val loss 对此不敏感（平坦），WER（可懂度）也鲁棒——只有 MCD 类细节指标能看见。缓解：后期 LR 衰减 / 按 val_mcd 选点 / 多 checkpoint 权重平均（soup）

### MCD 标定结论（重要，已写进 metrics.py 文档）

- 本提取器（log-mel 80 + DCT）与论文常用 SPTK-mcep **量纲不同**，绝对值只做同提取器下的相对比较
- 排查链：往返 3.65（链路无损）→ ASR 逐词全对（输出可懂）→ GT 自变速 1.81（DTW 正确）→ mel 图对比
- **最终定性：模型输出"可懂但细节偏糊"**（140ep + 10 步 ODE 少步采样的典型现象），MCD 偏高反映的是细节损失而非内容错误
- 改进判据：同文本 MCD 应低于跨语句自然语音基线（约 55~90dB），最终逼近 3.6dB 下限

## 五、ConvNeXt V2 局部算子替换（未训练，代码就绪）

**范围决策**：只换 Decoder 的特征提取块（"只换 CNN、不改框架"）；TextEncoder 不动。
概念澄清：ConvNeXt V2 是"块设计"不是"卷积替代品"——1×1 投影/采样层/输出头保留（ConvNeXt 官方自己也保留）。

| 文件 | 内容 |
|---|---|
| `matcha/models/components/convnext_v2.py` | `GlobalResponseNorm1D`（GRN）、`ConvNeXtV2Unit1D`（k7 深度卷积+LN+倒瓶颈+GRN+内部残差/LayerScale，替代 Block1D）、`ConvNeXtV2ResBlock1D`（替代 ResnetBlock1D，时间注入/残差外壳与原版对齐） |
| `decoder.py` | 仅加 `resnet_type` 开关（默认 `"conv"`=原版）；down/mid/up/skip/Transformer/采样层零改动 |
| `configs/model/decoder/convnext_v2.yaml` | 变体配置 |

**训练命令**（嵌套组覆盖用斜杠，点号会被当普通键）：

```powershell
python matcha/train.py experiment=ljspeech_min_memory model/decoder=convnext_v2
# 或等价：+model.decoder.resnet_type=convnext_v2
```

**验证**：GRN 零初始化、前向/反向、掩码清零 padding、时间条件敏感、默认路径回归、hydra 组合 + instantiate 端到端全过。参数量（torchinfo 实测）：U-Net 基线全模型 18.2M（encoder 7.2M + decoder 11.0M）→ ConvNeXt 版全模型 22.5M（decoder 15.3M）；多出部分主要是每单元 4× 升维的 pointwise 层。

### 当日修掉的两个 bug

1. **GRN 死路（自写实现 bug）**：GRN 零初始化 + 单元无内部残差 → 单元初始输出与输入无关 → 时间条件被抹掉。按官方结构补回**内部残差 + LayerScale(1e-6)**。
2. **上游遗留**：`Decoder.__init__` Python 默认 `act_fn="snake"` 在 FeedForward 无此分支（训练未炸只因 hydra 传的是 `snakebeta`）；已对齐修正为 `snakebeta`。
